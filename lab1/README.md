# ЛР1: JSONB-документы бронирований

**Цель:** преобразовать данные демобазы «Авиаперевозки» в документы JSONB
и добавить заметку бронированиям с рейсами в аэропорты, чьи часовые пояса
отличаются от московского строго больше чем на шесть часов.

[PDF-отчёт](output/pdf/report.pdf) · [Весь SQL](lab1.sql) · [Запуск проекта](../README.md#быстрый-запуск)

## Результат

| Показатель | Значение |
|---|---:|
| Исходные бронирования | 262 788 |
| Документы в `bookings.bookings_json` | 262 788 |
| Бронирования с добавленной заметкой | 18 799 |
| Некорректные обязательные поля JSON | 0 |
| Расхождения в составе пассажиров | 0 |
| Пропущенные / ошибочно отмеченные брони | 0 / 0 |

Повторный запуск не меняет документы. Проверка с `ROLLBACK` подтверждает,
что существующий текст `notes` сохраняется, новая заметка не дублируется,
а остальные JSON-поля остаются прежними.

## Решение

В `bookings.bookings_json` хранятся первичный ключ `id`, внешний ключ
`booking_id`, документ `data JSONB` и время создания `created_at`.
`UNIQUE (booking_id)` обеспечивает один документ на бронирование.

Пассажиры собираются через `jsonb_build_object` и `jsonb_agg` после удаления
повторов. Статус `confirmed` — условное значение: в исходной таблице статуса
брони нет. Пример структуры документа после обновления (имя заменено условным обозначением):

```json
{
  "booking_number": "00000F",
  "status": "confirmed",
  "passengers": [{"id": "1708 262537", "name": "PASSENGER_001"}],
  "notes": "Бронирование содержит рейс в/из аэропорта с разницей во времени относительно Москвы более 6 часов."
}
```

Для поиска подходящих бронирований используются связи:

```text
bookings → tickets → ticket_flights → flights → airports_data
```

Проверяются оба конца каждого рейса. `AT TIME ZONE` вычисляет смещения
на дату вылета и прилёта. Условие `abs(...) > 6` учитывает оба направления
смещения и исключает случай ровно шести часов.

`jsonb_set` меняет только `notes`, `concat_ws` сохраняет предыдущий текст,
а проверка `position` предотвращает повторное добавление фразы.
`ON CONFLICT DO NOTHING` сохраняет уже созданные документы при повторном запуске.

## Запуск и проверка

Из корня репозитория после `docker compose up -d --wait`:

```sh
python scripts/prepare_demo.py
python scripts/run_labs.py --backend docker --lab 1
python scripts/verify_labs.py --backend docker --lab 1
```

На установленном PostgreSQL используйте те же команды без `--backend docker`.
Для ручной работы в pgAdmin подключитесь к базе `demo` и откройте `lab1.sql`.
Скрипт проверки сравнивает множества пассажиров в обе стороны и независимо
вычисляет ожидаемые бронирования через сравнение интервалов.

Подготовка исходной базы описана в [DATA_SOURCES.md](../DATA_SOURCES.md).
